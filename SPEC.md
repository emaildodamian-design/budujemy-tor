# SPEC — Budujemy Tor (v3)

> Source of truth for this project. v1 was a turn-taking co-play toy, v2 turned it into a
> track-building puzzle, v3 gives the puzzle a real difficulty curve. This file describes
> the game as it is now; the PR descriptions hold the done / not-done lists per version.

A small offline-first PWA, "Budujemy Tor": a calm track-building puzzle for one young child
(target: a pre-reader of about 6 who is good at logic and counting puzzles and is bored by
trivial tasks), with one parent beside them as a helper, on ONE phone. The challenge comes
from the puzzle, never from pressure.

## WORKING CONTRACT
- PWA for Chrome on Android (Google Pixel), installable, fully offline after first load.
  Static files only: no backend, no accounts, no analytics.
- Work on a feature branch and open a Pull Request. Do NOT merge it (merging deploys; the
  owner merges after a real-device playtest).
- Stop condition: the PR is open with CI green and a done / not-done list against the brief.

## CORE LOOP
- A board (max 6 columns × 7 rows, portrait) with a start shed, a depot (with a door on one
  side), scenery (rock, house, tree, lake), rivers (need a bridge), mountains (need a tunnel),
  stations (fixed track the train must pass, from chapter 4; in order from chapter 7), fixed
  one-way track (an arrow; chapter 6 on), and a tray of pieces: straight, curve, bridge, tunnel.
- The child lays pieces (tap or drag), turns them (tap), takes them back (hold or drag to the
  tray), then presses the engine button: the train test-runs the track and stops gently where
  it breaks. Every stop shows its cause with soft light (never red, no error sound).
- A session is 1 warm-up + 3 new levels (session 1: L01–L04), then a slow depot ride and the
  END screen "Koniec. Teraz: [card]", then the next-day lock.
- Help: 2 helper lamps per level (lamp 1: a flag on the halfway cell of the remaining route;
  lamp 2: the next cell, the tray piece and an outline of the piece). The stuck ladder offers
  help when runs stop getting further: lamp pulse → flag (or lamp-2 hint) → ghost path of every
  piece but the last (level marked helped). Hints never move, remove or rotate a piece.
- Adaptive, never announced: quiet skip after two clean first-run solves; a helped level comes
  back mirrored 2 sessions later; after a helped new level the next level's easier sibling is
  played first (mirrored); warm-ups come from 2+ chapters back.

## LEVELS AND DIFFICULTY
- 48 main levels in 8 chapters of 6, plus a step-down sibling for every practice level and the
  finale of chapters 2–8. Difficulty is measured by the solver (`src/game/metrics.ts`:
  minLen, solutions, distractors, naiveLen, detour, freeLen, countSlack, planDepth, lures,
  faults, arrowMatters, orderMatters) and every band in `src/game/bands.ts` is enforced in CI.
- Levels are generated by a seeded, reproducible generator (`npm run gen`, `npm run gen:set`)
  and picked for looks as well as numbers. L01–L04 ship exactly as given in the v3 brief.

## HARD SAFEGUARDS (acceptance-critical)
1. Before starting, the parent picks a "Potem" (next activity) card: bath, meal, walk, book,
   optionally with a photo stored ONLY locally (IndexedDB), shown at start and on the END screen.
2. NO "play again". After a session ends, a new one is locked until the next calendar day. The
   parent menu (hidden 3 s hold on the END / LOCKED heading) can unlock ("Odblokuj dziś").
3. Sound OFF by default; if enabled, only soft sounds.
4. NO points, stars, streaks, collectibles, badges, timers, ads, notifications, analytics or
   network calls.
5. A gentle 5 s look phase at each level start (soft ring, no numbers) before input.
6. One language per session (PL default; PT toggle in the parent settings).
7. Offline after first load (service worker + manifest); photos never leave the device.
8. No words on child-facing screens: icons, art, and digits on tray counts only. Parent screens
   (setup, parent menu, level preview and its bar) may use words.

## PARENT PREVIEW
- A 3 s hold on the setup title, or on the END / LOCKED heading, opens the parent menu:
  [Podgląd etapów], [Odblokuj dziś] (END / LOCKED only), [Wróć].
- The preview lists all levels and siblings by chapter with their measured difficulty and
  next / solved / helped marks; any level plays in a sandbox with a parent bar (show solution,
  previous / next, exit). Preview never counts as a session, never unlocks and never writes to
  storage, except "Ustaw jako następny" (3 s hold), which sets only the next level and clears
  the recent-solves memory.

## TECH
- Vanilla TypeScript + Vite (build only), no runtime dependencies. Pure game rules in
  `src/game/`, drawing and input in `src/ui/`.
- Vitest unit, property and happy-dom UI tests, run in CI together with the typecheck and the
  build. The level table `LEVELS.md` is generated and CI fails if it is stale.
- The README covers running locally, level generation and validation, the parent preview,
  deploying to GitHub Pages and installing on Android Chrome.
